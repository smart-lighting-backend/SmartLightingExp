# 设备离线告警通知接口开发日志

## 1. 开发目标

本次开发只在后端完成设备离线告警通知能力，不涉及前端页面或其他非后端模块。

实现目标：

- 设备离线时自动生成告警通知记录。
- 避免同一设备重复生成未恢复的离线告警。
- 设备恢复上报遥测后，自动恢复离线告警。
- 提供告警记录分页查询接口。
- 提供告警详情查询接口。

当前项目已有 `alarm_record` 告警记录表，因此本次“告警通知”落地为后端告警记录数据，供后续页面、轮询、WebSocket 或其他通知通道继续消费。

## 2. 涉及文件

## 3. 数据表说明

使用已有表：

```text
alarm_record
```

核心字段：

| 字段 | 说明 |
|---|---|
| `id` | 告警主键 |
| `device_id` | 设备编号 |
| `type` | 告警类型，例如 `OFFLINE` |
| `level` | 告警级别，例如 `MAJOR` |
| `status` | 告警状态：`ACTIVE`、`ACKNOWLEDGED`、`RECOVERED` |
| `reason` | 告警原因 |
| `start_at` | 告警开始时间 |
| `recover_at` | 告警恢复时间 |
| `handler` | 处理人或系统处理标识 |

## 4. 离线判定规则

### 4.1 检测周期

通过定时任务 `DeviceOfflineMonitor` 每 60 秒检测一次：

```java
@Scheduled(initialDelay = 60000, fixedRate = 60000)
```

含义：

- 应用启动 60 秒后执行首次检测。
- 之后每 60 秒执行一次。

### 4.2 检测范围

只检测启用且未删除的设备：

```text
enabled = true
deleted = false
```

### 4.3 离线条件

设备满足以下任一条件，即判定为离线：

```text
lastHeartbeatAt IS NULL
```

或：

```text
lastHeartbeatAt < 当前时间 - 5 分钟
```

离线阈值在服务中定义：

```java
OFFLINE_THRESHOLD_MINUTES = 5
```

## 5. 离线告警生成逻辑

当设备被判定为离线后，后端执行两件事。

### 5.1 更新设备状态

设备状态更新为离线：

```text
device.status = 2
```

其中设备状态约定：

| 状态值 | 含义 |
|---|---|
| `0` | 停用 |
| `1` | 在线 |
| `2` | 离线 |
| `3` | 异常 |

### 5.2 生成告警记录

新增一条告警记录：

| 字段 | 写入值 |
|---|---|
| `deviceId` | 当前设备编号 |
| `type` | `OFFLINE` |
| `level` | `MAJOR` |
| `status` | `ACTIVE` |
| `reason` | 根据心跳情况生成 |
| `startAt` | 当前检测时间 |

告警原因示例：

```text
设备未上报心跳，判定为离线
```

或：

```text
心跳中断超过 5 分钟，最后心跳时间：2026-07-02 10:20:30
```

## 6. 防重复告警规则

为了避免定时任务每分钟重复插入同一设备的离线告警，生成前会先查询该设备是否已有未关闭的离线告警。

未关闭告警状态包括：

```text
ACTIVE
ACKNOWLEDGED
```

查询条件：

```text
device_id = 当前设备编号
type = OFFLINE
status IN (ACTIVE, ACKNOWLEDGED)
```

如果已存在，则只更新设备状态，不再重复生成 `alarm_record`。

## 7. 设备恢复逻辑

设备重新上报 MQTT 遥测数据时，由 `MqttSubscriber` 触发恢复流程。

### 7.1 触发位置

当订阅到：

```text
streetlight/+/telemetry
```

并成功解析、写入遥测数据后，执行：

```java
alarmRecordService.markDeviceOnline(deviceId, telemetry.getCollectedAt());
```

### 7.2 更新设备在线状态

设备状态更新为在线：

```text
device.status = 1
```

同时刷新心跳时间：

```text
device.last_heartbeat_at = telemetry.collected_at
```

原有最新数据快照仍会继续更新：

```text
device.latest_data = 当前 MQTT payload
```

### 7.3 恢复离线告警

如果该设备存在未关闭的离线告警，则更新为已恢复：

| 字段 | 更新值 |
|---|---|
| `status` | `RECOVERED` |
| `recoverAt` | 当前遥测采集时间或当前时间 |
| `handler` | `system` |

恢复范围：

```text
device_id = 当前设备编号
type = OFFLINE
status IN (ACTIVE, ACKNOWLEDGED)
```

## 8. 告警分页查询接口

### 8.1 接口

```http
GET /api/alarms/page
```

### 8.2 请求参数

| 参数 | 类型 | 是否必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `pageNum` | Long | 否 | `1` | 当前页码，小于 1 时按 1 处理 |
| `pageSize` | Long | 否 | `10` | 每页条数，小于 1 时按 1 处理，最大 100 |
| `deviceId` | String | 否 | 无 | 按设备编号过滤 |
| `type` | String | 否 | 无 | 告警类型，例如 `OFFLINE` |
| `level` | String | 否 | 无 | 告警级别，例如 `MAJOR`、`CRITICAL` |
| `status` | String | 否 | 无 | 告警状态，例如 `ACTIVE`、`ACKNOWLEDGED`、`RECOVERED` |
| `startTime` | DateTime | 否 | 无 | 告警开始时间下限，ISO 日期时间格式 |
| `endTime` | DateTime | 否 | 无 | 告警开始时间上限，ISO 日期时间格式 |

### 8.3 排序规则

分页查询按告警开始时间和主键倒序：

```text
startAt DESC, id DESC
```

### 8.4 请求示例

```http
GET /api/alarms/page?pageNum=1&pageSize=10&type=OFFLINE&status=ACTIVE
```

按设备和时间范围查询：

```http
GET /api/alarms/page?deviceId=SL-004&startTime=2026-07-02T00:00:00&endTime=2026-07-02T23:59:59
```

## 10. 核心方法说明

### 10.1 `scanOfflineDevices`

职责：

- 扫描所有启用且未删除的设备。
- 找出心跳为空或心跳超时的设备。
- 调用离线处理逻辑。

### 10.2 `markDeviceOffline`

职责：

- 将设备状态更新为离线。
- 判断是否已有未关闭离线告警。
- 无未关闭告警时新增 `OFFLINE` 告警记录。

### 10.3 `markDeviceOnline`

职责：

- 设备上报遥测后，将设备状态恢复为在线。
- 刷新设备最后心跳时间。
- 将未关闭的离线告警恢复为 `RECOVERED`。

### 10.4 `pageAlarms`

职责：

- 根据分页参数查询告警列表。
- 支持按设备、类型、级别、状态、时间范围过滤。
- 最大分页大小限制为 100，避免一次查询过多数据。

## 11. 与现有功能的关系

### 11.1 与 MQTT 遥测接收的关系

原有 `MqttSubscriber` 会：

- 解析遥测 payload。
- 插入 `telemetry`。
- 更新 `device.latest_data`。
- 触发策略引擎评估。

本次新增后，接收到遥测时还会：

- 更新设备在线状态。
- 刷新最后心跳时间。
- 自动恢复该设备的离线告警。

### 11.2 与设备管理状态的关系

离线检测只处理：

```text
enabled = true
deleted = false
```

因此：

- 已停用设备不会生成离线告警。
- 已逻辑删除设备不会生成离线告警。
