## 一、IR-05 视觉感知事件（IN-04）

### 验证目标
确认系统能生成、存储、展示 AI 视觉识别事件。

### 测试步骤

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 启动后端（确保 `mock.enabled: true`），等待 20 秒 | 日志出现 `👁 vision event:` 字样 |
| 2 | 登录前端 → 侧边栏点击「事件中心」 | 页面加载，默认显示「👁 视觉事件」Tab |
| 3 | 等待 5 分钟（MockDataGenerator 运行周期） | 表格中出现行人检测/车辆通行等记录 |
| 4 | 选择事件类型筛选「行人检测」→ 点查询 | 仅显示行人检测类型的事件 |
| 5 | 在设备筛选框中输入特定设备编号 → 点查询 | 仅显示该设备的视觉事件 |
| 6 | 观察置信度进度条 | 绿色(≥90%) / 橙色(70-90%) / 红色(<70%) |
| 7 | 切换设备，观察不同设备的事件密度差异 | 不同设备有不同的事件分布（有的多有的少） |

### 验证数据流

```
MockDataGenerator → MQTT topic: streetlight/{id}/vision/event
    → MqttSubscriber 收到 → INSERT vision_event 表
    → 前端 GET /api/vision-events/page → EventCenter 展示
```

## 二、IR-06 语音告警事件（IN-05）

### 验证目标
确认系统能产生两种语音事件：随机播报 + 策略联动告警。

### 测试步骤

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 事件中心 → 切换到「🔊 语音事件」Tab | 显示语音事件列表 |
| 2 | 等待 MockDataGenerator 运行 | 出现随机播报/广播类型的事件（含中文内容） |
| 3 | 打开策略管理 → 编辑「深夜节能模式」 → 勾选「开启语音播报提示」 → 保存 | 策略 voiceAlert=true |
| 4 | 等待遥测数据触发该策略（光照<30 + 时段 23:00-05:00） | 策略被命中 |
| 5 | 刷新事件中心 → 语音事件 Tab | 出现一条 `策略触发: 深夜节能模式 → DIMMING(30)` 的警告记录 |
| 6 | 观察类型 Tag 颜色 | 警告=红色、播报=蓝色、广播=灰色 |

### 验证数据流（双源）

```
源1: MockDataGenerator 随机 → MQTT → voice_event 表
源2: DecisionEngine 策略命中 + voiceAlert=true → 直接 INSERT voice_event 表
前端: GET /api/voice-events/page → EventCenter 展示
```

## 三、IR-07 预测性维护与健康评分（IN-06）

### 验证目标
确认 ACK 机制工作 + 健康评分定时计算 + 前端展示。

### 测试步骤

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 等待 MockDataGenerator 运行几轮（15-20 分钟） | 日志出现 `ACK simulation: N commands acknowledged` |
| 2 | 进入设备详情页（DeviceDetail） | 页面显示「设备健康评分」卡片 |
| 3 | 观察健康评分环形图 | 分数在 60-100 之间，颜色对应等级 |
| 4 | 展开 4 个维度进度条 | 每个维度有分数、权重、降分原因 |
| 5 | 阅读降分原因 | 如"近7天离线1次"、"部分指令未收到设备确认" |
| 6 | 切换不同设备 | 不同设备分数不同（LAMP-003 可能较低因为模拟数据中它离线多） |
| 7 | 设备列表页 | 健康评分列显示分数和进度条 |
| 8 | 手动触发健康评分：`GET /api/devices/{id}/health` | 返回 JSON 含 overallScore, dimensions, suggestion |

### 验证 ACK 机制

```
后端日志搜索 "ACK received" → 确认有 ACK 确认记录
数据库查询: SELECT COUNT(*) FROM control_command WHERE ack_at IS NOT NULL
→ 应有大约 90% 的指令有 ack_at（模拟器中 90% 概率）
```

## 四、IN-01 多模态感知融合面板

### 验证目标
确认设备详情页能在一个面板中聚合展示所有感知维度。

### 测试步骤

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 进入 DeviceDetail 页面 | 在设备信息卡片下方看到「融合感知面板」 |
| 2 | 观察 8 格传感器网格 | 光照/温度/湿度/PM2.5/AQI/PIR/车流量/健康分 每格有数值 |
| 3 | 观察 PIR 格子 | 显示绿色"有人"Tag 或灰色"无人"Tag |
| 4 | 观察视觉事件行 | 显示最新一条视觉事件（类型+置信度+时间）或"暂无视觉事件" |
| 5 | 观察语音事件行 | 显示最新一条语音事件（类型+内容+时间）或"暂无语音事件" |
| 6 | 观察告警行 | 显示最近 3 条告警记录或"暂无告警记录" |
| 7 | 切换到另一个设备 | 面板数据随设备切换而更新 |
| 8 | 访问一个没有视觉/语音事件的设备（如刚创建的） | 视觉/语音行显示"暂无"，不报错 |

### 验证 API

```
GET /api/devices/{deviceId}/perception
→ 返回 telemetry, latestVision, latestVoice, recentAlarms, healthScore
```

## 五、IR-04 策略编排完善（本次新增）

### 验证目标
确认策略执行历史可查、模拟测试可用。

### 测试步骤 — 执行历史

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 进入策略配置页面 | 每个策略卡片增加绿色「历史」按钮 |
| 2 | 点击任意策略的「历史」按钮 | 弹出弹窗，显示策略名称和近 7 天触发次数 |
| 3 | 观察执行记录列表 | 显示最近 30 条（时间、设备、执行动作） |
| 4 | 点击尚未触发过的策略 | 弹窗显示"暂无执行记录" |
| 5 | 切换不同策略查看 | 不同策略的触发次数差异明显 |

### 测试步骤 — 模拟测试

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 进入新建/编辑策略页面 | 保存按钮旁有「模拟测试」按钮 |
| 2 | 点击「模拟测试」 | 弹出输入框：光照/温度/湿度/PIR/车流量 |
| 3 | 输入 `illuminance=20, pir=0, trafficFlow=5` → 点「开始测试」 | 显示"匹配成功！命中策略 XXX，执行 DIMMING(N)" |
| 4 | 输入 `illuminance=500, pir=0, trafficFlow=50` → 测试 | 显示"未匹配任何策略" |
| 5 | 观察所有策略的命中/未命中列表 | 每个策略后有绿色"命中"或灰色"未命中"标签 |
| 6 | 修改策略条件后立即测试 | 结果随条件变化而更新，无需等待真实数据 |
