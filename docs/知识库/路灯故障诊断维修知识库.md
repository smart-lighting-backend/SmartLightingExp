# 智慧路灯故障诊断与维修知识库

> 用于导入 MaxKB 知识库，作为 RAG 维修助手的数据源  
> 覆盖：电源、通信、传感器、光源、控制、结构六大类故障

---

## 一、电源类故障

### 1.1 灯完全不亮

**症状：** 设备状态离线，最后心跳时间超过阈值，前端显示"离线"。

**可能原因及排查顺序：**

1. **供电线路故障**
   - 检查配电箱空开是否跳闸
   - 测量路灯接线端子电压，正常应为 AC 220V ±10%
   - 检查电缆是否有破损、老化、接头松动

2. **电源模块损坏**
   - 测量电源模块输出端直流电压（通常为 12V/24V/48V，取决于型号）
   - 电源模块指示灯不亮 → 更换电源模块
   - 电源模块有异响、焦味 → 立即断电更换

3. **保险丝熔断**
   - 检查设备内部保险丝是否熔断
   - 更换同规格保险丝（切勿使用更大电流规格）
   - 如果更换后再次熔断 → 存在短路，需进一步排查

4. **浪涌保护器动作**
   - 雷雨天气后常见
   - 检查 SPD 状态窗口：绿色=正常，红色=需更换
   - 更换后检查接地电阻是否合格（≤4Ω）

**维修建议：** 优先从配电箱开始逐级排查，最后检查设备内部。

---

### 1.2 灯忽明忽暗（闪烁）

**症状：** 设备在线，但亮度不稳定，遥测数据显示亮度值频繁波动。

**可能原因：**

1. **供电电压不稳**
   - 测量输入电压是否在 AC 198V-242V 范围内
   - 用电高峰期电压偏低 → 需要稳压器
   - 同线路多盏灯都有此现象 → 配电线路问题

2. **驱动电源老化**
   - LED 驱动电源使用超过 3 年 → 输出纹波增大
   - 更换同规格 LED 驱动电源
   - 注意驱动电源的输出电流必须与 LED 模组匹配

3. **调光信号干扰**
   - 检查 PWM 调光线是否与强电线缆并行走线
   - 调光线应使用屏蔽线，屏蔽层单端接地
   - 0-10V 调光信号线长度不宜超过 50 米

4. **灯具散热不良**
   - 检查散热器是否被灰尘、树叶堵塞
   - LED 结温过高会触发过温保护 → 降功率 → 恢复 → 再保护 → 闪烁循环
   - 清洁散热器，检查风扇（如有）是否正常运转

---

### 1.3 灯亮度明显不足

**症状：** 设备在线，brightness=100% 但实际亮度远低于正常值。

**可能原因：**

1. **LED 模组光衰**
   - LED 正常使用寿命约 50000 小时（约 5-6 年连续运行）
   - 光衰超过 30%（L70）即应更换
   - 用照度计测量实际照度，与同型号新灯对比

2. **驱动电源输出电流偏低**
   - 测量驱动电源实际输出电流
   - 老化导致输出电流下降 → 更换驱动电源

3. **灯罩脏污**
   - 清洁灯罩表面灰尘、鸟粪、油污
   - 透明 PC 灯罩老化发黄 → 更换灯罩
   - 建议每半年清洁一次

4. **调光信号异常**
   - 检查 control_command 表，确认最近指令实际亮度值
   - 确认调光协议匹配（0-10V / PWM / DALI）
   - 短路调光线测试（部分驱动电源短路调光线=100%亮度）

## 二、通信类故障

### 2.1 设备频繁离线/在线交替

**症状：** alarm_record 中出现多条 OFFLINE 告警，设备在线时长不连续。

**可能原因：**

1. **4G/WiFi 信号弱**
   - 检查设备安装位置信号强度
   - 天线是否被金属灯壳完全屏蔽 → 天线外置或更换位置
   - 4G 设备：检查 SIM 卡接触、欠费、信号覆盖

2. **网关负载过高**
   - 同网关下设备数量超过 50 台 → 考虑分流或增加网关
   - 检查网关 CPU/内存使用率
   - 减少不必要的上报频率

3. **MQTT 心跳间隔配置问题**
   - 心跳间隔建议 60 秒（Keep Alive 不低于 90 秒）
   - 如果心跳间隔太短 → 弱网下容易丢包判定离线
   - 如果心跳间隔太长 → 离线发现不及时

4. **设备供电间歇性中断**
   - 检查接线端子是否松动（热胀冷缩导致）
   - 检查空开是否老化导致误跳闸

---

### 2.2 MQTT 连接失败

**症状：** 设备端日志显示 MQTT connect 失败，后端显示设备离线。

**排查步骤：**

1. 确认 EMQX Broker 地址、端口、用户名、密码是否正确
2. 确认 client-id 唯一，未被其他设备重复使用
3. 检查防火墙是否放行 MQTT 端口（默认 1883）
4. 使用 MQTT 客户端工具（如 MQTTX）从同网络环境测试连接
5. 检查设备 DNS 解析是否正常（如果使用域名而非 IP）

---

### 2.3 数据上报延迟大

**症状：** 遥测数据采集中间间隔远超预期（正常约 5 分钟），通信质量健康维度评分低。

**可能原因：**

1. 网络延迟高 → 检查 ping 值，4G 网络一般在 50-200ms
2. 设备 CPU 负载高 → 检查是否有死循环或内存泄漏
3. Broker 性能瓶颈 → 检查 EMQX 连接数和消息吞吐量
4. 传感器读取耗时 → 部分传感器（如 PMS5003）有预热时间

---

## 三、传感器类故障

### 3.1 光照传感器读数异常

**症状：** illuminance 值始终为 0、NULL，或超出合理范围（<0 或 >200000）。

**可能原因：**

1. **传感器接口松动**
   - BH1750 等光照传感器使用 I2C 接口
   - 检查 SDA/SCL 线连接，上拉电阻是否正常
   - 重新插拔传感器模块

2. **传感器损坏或污染**
   - 传感器窗口被灰尘、水雾遮挡 → 清洁
   - 用手机手电筒照射传感器，观察读数是否变化
   - 不变化 → 传感器损坏，更换

3. **I2C 地址冲突**
   - 同总线上其他设备占用了 BH1750 的地址
   - 默认地址 0x23，ADDR 引脚拉高为 0x5C
   - 检查是否有地址冲突

---

### 3.2 温湿度传感器读数异常

**症状：** 温度读取 -999°C 或 >80°C（不合理高），湿度 >100% 或 <0%。

**可能原因：**

1. **DHT22 传感器故障**
   - DHT22 在高温高湿环境下寿命约 1-2 年
   - 读数跳变到极端值 → 传感器已损坏，更换
   - 确认数据线有 4.7k-10kΩ 上拉电阻

2. **传感器受阳光直射**
   - 传感器壳体安装在灯杆内部，不应直接暴露在阳光下
   - 温度读数偏高通常是安装位置问题而非传感器故障
   - 加装防辐射罩

3. **接线氧化**
   - 长期户外运行导致接线端子氧化
   - 清洁端子或更换接线

---

### 3.3 PM2.5 传感器读数异常

**症状：** pm25 值始终为 0 或超高（>500），或频繁跳变。

**可能原因：**

1. **PMS5003 风扇故障**
   - 传感器内部风扇停转 → 空气无法流通 → 读数异常
   - 听传感器是否有风扇运转声
   - 风扇停转 → 整模块更换

2. **传感器进气口堵塞**
   - 灰尘、虫网堵塞进气口 → 清洁
   - 建议在进气口加装防虫网

3. **激光器老化**
   - PMS5003 激光器寿命约 3 年
   - 老化后读数偏差增大 → 更换

---

### 3.4 PIR 人体红外传感器误报/漏报

**症状：** pir 值始终为 1（一直检测到人）或始终为 0（检测不到人）。

**可能原因：**

1. **安装角度偏移**
   - HC-SR501 检测范围：锥形 110°，距离 3-7 米
   - 方向偏了 → 调整安装角度

2. **环境温度过高**
   - 夏季高温（>35°C）时，人体与背景温差小 → 灵敏度降低
   - 调节传感器灵敏度电位器

3. **被遮挡**
   - 灯杆上的广告牌、树枝、蜘蛛网遮挡 → 清除遮挡物

---

## 四、LED 光源故障

### 4.1 部分灯珠不亮

**症状：** 灯具局部暗区，整体亮度不足。

**可能原因：**

1. **单颗 LED 死灯**
   - 个别 LED 开路 → 如果是串联回路，整串不亮
   - 如果是并联+串联混合，仅坏的那颗不亮
   - 少量死灯不影响继续使用，超过 10% 建议更换模组

2. **焊点虚焊**
   - 温度循环导致焊点开裂
   - 用放大镜检查 LED 焊点
   - 回流焊修复或更换模组

3. **铝基板变形**
   - 长期高温导致铝基板弯曲
   - 更换模组并检查散热条件

---

### 4.2 色温/显色性变化

**症状：** 灯光颜色偏蓝/偏黄，与安装时不一致。

**可能原因：**

1. **荧光粉老化** → LED 模组色温漂移 → 更换模组
2. **不同批次灯珠混用** → 统一更换同批次模组
3. **驱动电流异常导致色偏** → 检查/更换驱动电源

---

## 五、控制系统故障

### 5.1 自动策略不生效

**症状：** 策略已启用，遥测数据满足条件，但未下发控制指令。

**排查步骤：**

1. 查看 decision_log 表，确认是否有 MATCH_EXECUTED 或 NO_MATCH 记录
2. 查看策略 conditions JSON 格式是否正确
3. 确认设备不在手动控制锁定期内（manual_mode=1 且 manual_expire_at > 当前时间）
4. 使用 POST /api/policies/test 接口模拟测试策略匹配
5. 确认 decision_log.matchedPolicy 字段与策略名称一致

---

### 5.2 手动控制指令无响应

**症状：** 前端下发指令，设备未执行，无 ACK 回复。

**排查步骤：**

1. 查看 control_command 表，确认 status 是 SENT（未 ACK）还是 EXECUTED（已 ACK）
2. 确认 MQTT 发布成功（后端日志 search "MQTT published"）
3. 确认设备订阅了 streetlight/{deviceId}/command topic
4. 检查指令格式：action 应为 ON/OFF/DIMMING(N)
5. 检查设备端 MQTT 客户端是否在线

---

### 5.3 健康评分异常偏低

**症状：** health_score 很低（<50），但设备实际运行正常。

**排查思路：**

1. 查看各维度分项得分：离线频次、通信质量、指令响应率、传感器状态
2. 定位具体拉分维度：
   - 离线频次低 → 网络/供电问题
   - 通信质量低 → 上报间隔不稳定
   - 指令响应率低 → ACK 丢失或设备不回复
   - 传感器异常率高 → 检查 latestData 各字段是否在合理范围
3. 综合分析后安排针对性维修

## 六、结构与环境类故障

### 6.1 灯具进水

**症状：** 灯罩内有水雾、水滴，设备异常离线。

**处理步骤：**

1. 立即断电
2. 打开灯具排水孔，排空积水
3. 晾干内部电路板（自然晾干 24 小时或用热风枪低温吹干）
4. 检查密封胶圈是否老化，更换密封圈
5. 检查灯壳是否有裂缝，打胶修补或更换

---

### 6.2 灯杆倾斜/松动

**症状：** 灯杆明显倾斜，地脚螺栓松动。

**处理：**

1. 设置警戒区域，禁止行人车辆靠近
2. 检查地脚螺栓，重新紧固
3. 倾斜超过 5° → 需要重新校正
4. 基础混凝土开裂 → 需要重新浇筑

---

## 七、预防性维护建议

| 周期 | 维护内容 |
|------|----------|
| **每周** | 查看平台告警中心，处理新增告警；关注健康评分下降的设备 |
| **每月** | 导出健康评分报告，对评分 <60 的设备安排检查 |
| **每季** | 清洁灯罩和传感器窗口；检查接线端子紧固情况 |
| **每半年** | 测量关键设备照度值，与安装时对比；校准传感器 |
| **每年** | 全面巡检所有灯具；更换老化密封圈；检测接地电阻 |

## 八、备件更换参考

| 备件 | 平均寿命 | 更换标准 |
|------|----------|----------|
| LED 模组 | 50000h（5-6年） | 光衰 >30% 或死灯 >10% |
| LED 驱动电源 | 30000h（3-4年） | 输出电流偏差 >10% |
| 光照传感器 | 3-5年 | 读数漂移 >50% 或始终恒定 |
| DHT22 温湿度 | 1-2年 | 极端值频繁出现 |
| PMS5003 PM2.5 | 2-3年 | 激光器老化，风扇停转 |
| 电源模块 | 3-5年 | 输出纹波 >200mV |
| 密封胶圈 | 2-3年 | 硬化、开裂、失去弹性 |
| 4G/天线模块 | 3-5年 | 信号持续 < -100dBm |
