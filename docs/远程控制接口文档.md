# 远程控制 — 接口文档

> 对应功能：FR-08 远程设备控制
> 涉及后端文件：`ControlController.java`
> 涉及前端文件：`api/control.js`

---

## 一、发送控制指令

### 1.1 基本信息

| 项目 | 说明 |
|------|------|
| 接口 | `POST /api/devices/{deviceId}/control` |
| 鉴权 | 需要 Bearer Token（请求头 `Authorization: Bearer <token>`） |
| Content-Type | `application/json` |

### 1.2 请求参数

**路径参数：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| deviceId | string | 是 | 设备编号，如 `SL-001` |

**请求体（JSON）：**

```json
{
  "action": "ON",
  "brightness": 80
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `action` | string | 是 | 指令类型：`ON`（开灯）、`OFF`（关灯）、`DIMMING`（调光） |
| `brightness` | int | 否 | 亮度值 0~100，仅在 `action=DIMMING` 时必填 |

### 1.3 响应格式

**成功响应（200）：**

```json
{
  "code": 200,
  "msg": "success",
  "data": null
}
```

**业务错误响应（500）：**

```json
{
  "code": 500,
  "msg": "设备不存在",
  "data": null
}
```

| 错误场景 | HTTP 状态码 | `code` | `msg` |
|----------|-------------|--------|-------|
| 设备不存在 | 200 | 500 | "设备不存在" |
| 无效指令类型 | 200 | 500 | "无效指令类型，支持: ON/OFF/DIMMING" |
| DIMMING 缺少 brightness | 200 | 500 | "DIMMING 指令需提供 brightness 参数" |
| MQTT 下发失败 | 200 | 500 | "MQTT 下发失败" |

### 1.4 后端处理流程

```
请求到达
  → 校验设备是否存在
  → 校验 action 是否有效（ON / OFF / DIMMING）
  → DIMMING 校验 brightness 是否提供
  → 发布 MQTT 指令至 streetlight/{deviceId}/command
  → 写入 control_command 表（status=SENT）
  → 更新设备 lastManualAt（AI 策略锁定 30 分钟）
  → 记录审计日志
  → 返回 success
```

**注意：** 当前处于软件联调阶段，MQTT 下发后不等待设备回执。控制指令的 `control_command.status` 始终为 `SENT`，硬件接入 MQTT 回执后才会更新为 `SUCCESS` 或 `FAILED`。

## 二、查询控制历史

### 2.1 基本信息

| 项目 | 说明 |
|------|------|
| 接口 | `GET /api/devices/{deviceId}/control-history` |
| 鉴权 | 需要 Bearer Token |

### 2.2 请求参数

**路径参数：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| deviceId | string | 是 | 设备编号 |

**查询参数：**

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| page | int | 否 | 1 | 页码，从 1 开始 |
| size | int | 否 | 10 | 每页条数 |

### 2.3 响应格式

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "records": [
      {
        "id": 1,
        "deviceId": "SL-001",
        "action": "ON",
        "brightness": null,
        "source": "MANUAL",
        "operator": "admin",
        "status": "SENT",
        "issuedAt": "2026-07-03T14:30:00",
        "ackAt": null,
        "resultDetail": "手动控制-ON"
      }
    ],
    "total": 1,
    "size": 10,
    "current": 1,
    "pages": 1
  }
}
```

### 2.4 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `records[].id` | long | 自增主键 |
| `records[].deviceId` | string | 设备编号 |
| `records[].action` | string | 指令内容：`ON` / `OFF` / `DIMMING(70)` |
| `records[].brightness` | int/null | 调光亮度值，非调光指令时为 null |
| `records[].source` | string | 指令来源：`MANUAL`（手动）、`AUTO`（策略） |
| `records[].operator` | string | 操作人用户名 |
| `records[].status` | string | 指令状态：`SENT`（已下发）、`SUCCESS`（成功）、`FAILED`（失败） |
| `records[].issuedAt` | string | 下发时间（ISO 格式 `yyyy-MM-ddTHH:mm:ss`） |
| `records[].ackAt` | string/null | 设备回执时间（硬件阶段有值） |
| `records[].resultDetail` | string | 结果描述 |
| `total` | int | 总记录数 |
| `size` | int | 当前页大小 |
| `current` | int | 当前页码 |
| `pages` | int | 总页数 |

## 三、前端对接说明

### 3.1 命令映射

前端 `api/control.js` 已封装命令映射，**前端页面组件无需关心后端 action 命名**：

| 前端调用命令 | 后端 action | 说明 |
|-------------|-------------|------|
| `'turn_on'` | `ON` | 开灯 |
| `'turn_off'` | `OFF` | 关灯 |
| `'dim'` | `DIMMING` | 调光，需传 `params.brightness` |
| `'flash'` | — | 后端暂不支持，走 Mock 降级 |
| `'restart'` | — | 后端暂不支持，走 Mock 降级 |

### 3.2 调用方式

```js
import { sendControlCommand, getControlHistory } from '../api/control.js'

// 发送控制指令
const res = await sendControlCommand('SL-001', 'turn_on', {})
// res = { code: 200, message: '开灯指令已下发', data: { deviceId, command, params, feedback } }

// 调光
const res = await sendControlCommand('SL-001', 'dim', { brightness: 70 })

// 查询控制历史
const res = await getControlHistory('SL-001', 1, 10)
// res = { code: 200, data: { list: [...], total, page, pageSize } }
```

### 3.3 控制指令响应格式

成功时返回结构：

```json
{
  "code": 200,
  "message": "开灯指令已下发",
  "data": {
    "deviceId": "SL-001",
    "command": "turn_on",
    "params": {},
    "feedback": {
      "status": "SENT",
      "message": "设备已响应，灯光已开启",
      "executed_at": "2026-07-03 14:35:00"
    }
  }
}
```

### 3.4 降级机制

| 场景 | 行为 |
|------|------|
| 后端可达，指令成功 | 返回后端真实结果 |
| 后端返回业务错误 | 返回错误码和错误信息，**不会**降级 Mock |
| 后端不可达（网络异常） | 自动降级 Mock 数据，`mockStore` 记录降级次数 |
| `flash` / `restart` 指令 | 不走后端，始终使用 Mock 数据 |

### 3.5 控制历史字段映射

后端 `control_command` 表字段到前端展示字段的映射由 `api/control.js` 的 `adaptBackendHistory` 函数处理：

| 后端字段 | 前端字段 | 说明 |
|----------|---------|------|
| `id` | `id` | 格式化为 `CTL001` 风格 |
| `deviceId` | `device_id` | 设备编号 |
| `action` | `command` | `ON` → `turn_on`，`OFF` → `turn_off`，`DIMMING` → `dim` |
| — | `command_label` | 中文标签：开灯/关灯/调光 |
| `brightness` | `params.brightness` | 调光亮度 |
| `status` | `status` / `status_label` | `SENT/SUCCESS` → `success`（绿色），`FAILED` → `failed`（红色） |
| `issuedAt` | `created_at` | 下发时间 |
| `ackAt` | `executed_at` | 执行时间，null 时显示 `--` |
| `resultDetail` | `message` | 结果描述 |
