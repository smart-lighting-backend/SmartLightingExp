# 权限分配功能修复 — 前端对接说明

> 日期：2026-07-03 | 关联修改：[完整种子数据.sql](file:///d:/java_program/SmartLightingExp/database/完整种子数据.sql)

---

## 一、背景

给角色分配功能权限时，保存接口 `PUT /api/roles/{id}/permissions` 一直返回 **403**，原因：

1. 数据库 **缺少 `role:assign` 权限记录**
2. 即使补充后，旧 Token 也不包含该权限，需重新登录

---

## 二、前端修复步骤

### 步骤 1：重新登录

数据库已修复后，前端需要让用户**退出重新登录**，新 Token 才会包含 `role:assign` 权限。

```javascript
// 原登录流程不变
const res = await axios.post('/api/auth/login', { username, password })
// 新 Token 已包含 role:assign
localStorage.setItem('token', res.data.token)
```

### 步骤 2：确认 Token 包含 role:assign

登录后可通过 `/api/auth/me` 检查：

```javascript
const me = await axios.get('/api/auth/me')
console.log(me.data.permissions)
// 应包含: "role:assign"
```

### 步骤 3：权限分配保存

```javascript
// 勾选权限后保存
const checkedPermissionIds = [1, 2, 3, 5, 8, 13, ...] // 选中节点的 id 集合

await axios.put(`/api/roles/${roleId}/permissions`, {
  permissionIds: checkedPermissionIds
}, {
  headers: { Authorization: `Bearer ${localStorage.getItem('token')}` }
})
// ✅ 保存成功，不再返回 403
```

## 三、不需展示"角色管理"菜单

数据库中**固定 4 种角色**（超级管理员/市政人员/路灯管理员/安全应急人员），前端不应有"角色管理"页面或菜单入口。

| 角色编码 | 名称 | 说明 |
|:--------|:-----|:------|
| SUPER_ADMIN | 超级管理员 | 系统超级管理员，拥有所有权限 |
| MUNICIPAL | 市政人员 | 查看+配置+处理告警 |
| MAINTENANCE | 路灯管理员 | 设备维护+告警处理 |
| EMERGENCY | 安全/应急人员 | 仅告警查看+智能助手 |

> 注意：虽然"角色管理"没有独立页面，但**权限分配功能**保留在"权限管理"页面中——选择角色 → 勾选权限 → 保存。

## 四、角色列表接口的使用

`GET /api/roles` 接口正常可用，用于权限管理页面中的**角色下拉选择**：

```javascript
// 获取角色列表（供选择用）
const rolesRes = await axios.get('/api/roles', {
  headers: { Authorization: `Bearer ${token}` }
})
// rolesRes.data → [{ id, name, roleCode, description, permissionCodes }]

// 选择角色后加载权限树
const treeRes = await axios.get(`/api/permissions/tree?roleId=${selectedRoleId}`, {
  headers: { Authorization: `Bearer ${token}` }
})
// treeRes.data → 权限树，已勾选该角色拥有的权限
```

## 五、权限管理页面完整流程

```
1. 页面加载
   ├── GET /api/roles            → 下拉列表（4 种角色）
   └── GET /api/permissions/tree → 完整权限树（默认无勾选）

2. 选择角色
   └── GET /api/permissions/tree?roleId=X
       → 权限树重新加载，已拥有的权限自动勾选（checked: true）

3. 勾选/取消权限
   └── 前端收集所有 checked 状态的节点 id
       → checkedPermissionIds = [2, 11, 12, 21, ...]

4. 保存
   └── PUT /api/roles/{id}/permissions
       Body: { "permissionIds": [2, 11, 12, 21, ...] }
       → 覆盖式分配（先清空旧权限，再插入新权限）
       → 保存成功后提示"权限分配成功"

5. 验证
   └── 被分配权限的用户重新登录
       → 导航栏自动更新（新增/减少可见菜单）
       → 按钮自动显示/隐藏（新增/减少操作权限）
```
