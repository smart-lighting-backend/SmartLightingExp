# 模拟数据生成到入库流程

```
MockDataGenerator (定时任务, 每5分钟)
    │
    │  1. 查询所有 enabled=true 的设备
    │  2. 为每个设备生成随机遥测数据
    │  3. 序列化为 JSON → MqttPublisher.publish()
    │
    ▼
EMQX Broker (topic: streetlight/{deviceId}/telemetry)
    │
    ▼
MqttSubscriber.messageArrived()
    │
    │  1. JSON 反序列化为 Telemetry 实体
    │  2. telemetryMapper.insert(telemetry)  ← 存入 telemetry 表
    │  3. deviceMapper.update(latestData, status, heartbeat)  ← 更新设备快照
    │  4. DecisionEngine.evaluate()  ← 触发 AI 策略评估
    │  5. alarmRecordService.resolveOfflineAlarm()  ← 自动恢复离线告警
    │
    ▼
MySQL (smart_lighting_db)
    ├── telemetry 表      — 存储原始遥测记录
    └── device 表         — 更新最新数据快照 (latest_data)

## 涉及的关键类

| 类 | 职责 |
|------|------|
| `MockDataGenerator` | 定时生成模拟遥测数据，通过 MQTT 发布 |
| `MqttProperties` | 读取 MQTT 连接配置 |
| `MqttConfig` | 创建 MqttClient 连接 EMQX |
| `MqttPublisher` | 封装消息发布 |
| `MqttSubscriber` | 订阅遥测 topic，处理消息并入库 |
| `Telemetry` | 遥测数据实体，映射 telemetry 表 |
| `TelemetryMapper` | MyBatis-Plus Mapper |
| `DecisionEngine` | AI 策略引擎，评估后调整设备亮度 |

## 模拟数据格式

```json
{
  "deviceId": "LAMP-001",    // 设备编号
  "illuminance": 1234,       // 光照强度（lux）
  "temperature": 26.78,      // 温度（℃）
  "humidity": 65,            // 湿度（%）
  "pm25": 43,                // PM2.5 浓度（μg/m³）
  "aqi": 87,                 // 空气质量指数
  "pir": 1,                  // 人体红外 0-无人 1-有人
  "trafficFlow": 23,         // 车流量（辆/分钟）
  "collectedAt": "2026-07-04T10:30:00"  // 采集时间
}
```

## 触发方式

- **定时触发**：`@Scheduled(initialDelay = 20000, fixedRate = 300000)` — 启动 20s 后首次，之后每 5 分钟一次
- **条件控制**：`@ConditionalOnProperty(name = "mock.enabled", havingValue = "true")` — 可由 `application.yaml` 中 `mock.enabled` 开关
