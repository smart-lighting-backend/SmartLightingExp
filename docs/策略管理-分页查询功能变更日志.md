# 策略管理 — 分页与多条件混合查询功能变更日志

> 文档版本：1.0.0
> 生成日期：2026-07-03

---

## 变更背景

原有 `GET /api/policies` 仅支持全量查询策略列表，无法满足前端分页展示和多条件筛选的需求。新增 `POST /api/policies/list` 接口，支持分页 + 6 个筛选条件组合查询。

## 接口说明

### 新增接口

| 方法 | 路径 | 说明 |
|:----|:-----|:-----|
| `POST` | `/api/policies/list` | 按条件分页查询策略列表 |

### 请求参数

```json
{
  "name": "深夜",             // [可选] 策略名称，LIKE 模糊匹配
  "policyType": "TIME",       // [可选] 策略类型，精确匹配
  "enabled": true,            // [可选] 启用状态，精确匹配
  "priorityMin": 1,           // [可选] 优先级最小值 >=
  "priorityMax": 100,         // [可选] 优先级最大值 <=
  "effectiveTime": "22:00",   // [可选] 生效时段，LIKE 模糊匹配
  "page": 1,                  // 页码，默认 1
  "size": 20                  // 每页条数，默认 20
}
```

### 响应格式

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "records": [
      {
        "id": 1,
        "name": "深夜低亮策略",
        "policyType": "TIME",
        "conditions": "{\"start\":\"22:00\",\"end\":\"06:00\"}",
        "action": "brightness=30",
        "priority": 10,
        "enabled": true,
        "effectiveTime": "22:00-06:00",
        "deleted": false,
        "createTime": "2026-07-01T00:00:00"
      }
    ],
    "total": 1,
    "current": 1,
    "pages": 1
  }
}
```

### 筛选规则

| 字段 | 匹配方式 | SQL 效果 |
|:-----|:---------|:---------|
| `name` | LIKE 模糊 | `name LIKE '%深夜%'` |
| `policyType` | 精确匹配 | `policy_type = 'TIME'` |
| `enabled` | 精确匹配 | `enabled = true` |
| `priorityMin` | >= | `priority >= 1` |
| `priorityMax` | <= | `priority <= 100` |
| `effectiveTime` | LIKE 模糊 | `effective_time LIKE '%22:00%'` |

默认过滤 `deleted = false`（仅查未删除策略），按 `priority` 升序排列。
