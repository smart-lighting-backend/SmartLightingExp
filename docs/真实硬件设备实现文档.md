## 四、遥测数据格式

设备每 ~1.5 秒上报一次，JSON 格式：

```json
{
  "deviceId": "Real_CS_001",
  "illuminance": 245.3,
  "led_status": "ON",
  "led_source": "AUTO",
  "brightness": 100
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| deviceId | string | 设备编号 |
| illuminance | float | 光照强度 (lux) |
| led_status | string | 灯状态: ON/OFF |
| led_source | string | 控制来源: AUTO(边缘决策)/MANUAL(云端指令) |
| brightness | int | 亮度百分比 0-100 |

> 注意: 小熊派只有 BH1750 光照传感器，温湿度/PM2.5/AQI/PIR/车流量等字段不上报，TDengine 中对应列为 NULL。

## 五、云端指令格式

后端通过 MQTT 下发到 `streetlight/Real_CS_001/command`：

```json
{
  "action": "ON",
  "issuedAt": "2026-07-17T20:30:00",
  "source": "MANUAL",
  "operator": "admin"
}
```

### 支持的指令

| action | 说明 | 硬件行为 |
|--------|------|---------|
| `ON` | 开灯 | PWM 占空比 100% |
| `OFF` | 关灯 | PWM 停止 |
| `DIMMING(60)` | 调光到 60% | PWM 占空比 60% |
| `AUTO` | 解除手动控制 | 立即恢复边缘决策 |
| `RESTART` | 重启设备 | 断开 MQTT 后重连 |

> `DIMMING(60)` 中括号内数字为亮度百分比，范围 0-100。

## 六、边缘决策逻辑

设备本地自主判断开关灯，不依赖云端：

- 光照 < 20 lux → 自动开灯
- 光照 >= 20 lux → 自动关灯
- 手动模式超时 30 分钟后 → 自动回退

```
┌──────────────────────────┐
│ 收到云端 ON/OFF/DIMMING   │ → LED_SOURCE = MANUAL, 启动30分钟倒计时
│                          │
│ 收到云端 AUTO             │ → LED_SOURCE = AUTO, 立即恢复边缘决策
│                          │
│ 手动模式中                │ → 跳过边缘决策
│ 手动超时                  │ → 自动回退 AUTO
│                          │
│ 自动模式 + Lux < 20       │ → PWM 100%, 开灯
│ 自动模式 + Lux >= 20      │ → PWM 0%, 关灯
│                          │
│ MQTT 断线                │ → 边缘决策继续工作 (纯本地)
└──────────────────────────┘
```

## 八、Flash 配置存储

Hi3861 内部 Flash 末尾 256 字节用于存储设备配置：

```
地址 0x5FF000 (偏移 0x1FF000)
┌──────────┬──────────────────┬──────────┐
│ 字段     │ 大小             │ 示例     │
├──────────┼──────────────────┼──────────┤
│ magic    │ 4B (0xBEA70001)  │ 有效标记 │
│ wifi_ssid│ 32B              │ OnePlus..│
│ wifi_pwd │ 32B              │ 88888888 │
│ device_id│ 32B              │ Real_CS..│
│ broker   │ 32B              │ 47.96... │
│ port     │ 2B               │ 1883     │
│ username │ 32B              │ Real_CS..│
│ password │ 64B              │ RealAAA..│
│ reserved │ 26B              │ 保留     │
└──────────┴──────────────────┴──────────┘
```

配置流程:
1. 首次上电 → Flash 无有效 magic → 使用硬编码默认值 → 写入 Flash
2. 下次上电 → magic 有效 → 读取 Flash 配置
3. 远程改 WiFi → MQTT `/config` 下发 JSON → 写入 Flash → 手动 RESET

## 十、MQTT 命令接收机制

小熊派的 Paho MQTT 库中 `MQTTYield` 无法正常接收消息。解决方法是每 ~500ms 调用一次 `MQTTSubscribe` 对 command 主题重订阅——该函数内部读取 SUBACK 时会顺带处理 Broker 推送的 PUBLISH 消息。

```c
while (1) {
    for (i = 0; i < 3; i++) {          // 3次 × 500ms = 1.5秒
        if (g_mqtt_connected) {
            MQTTSubscribe(&g_client, cmd_topic, 2, message_arrived);
            osDelay(500);
        } else {
            osDelay(500);
        }
    }
    // 传感器采集 + 边缘决策 + 遥测上报
    // 断线重连
}
```

## 十一、PWM 调光配置

```
GPIO_7 → PWM0 输出
频率: 40KHz (周期 40000 个计数)
占空比: 0-40000 对应 0%-100%
```

```c
static void pwm_set_brightness(int percent) {
    unsigned short duty = (unsigned short)(percent * 400);
    if (percent <= 0) {
        PwmStop(WIFI_IOT_PWM_PORT_PWM0);
    } else {
        PwmStart(WIFI_IOT_PWM_PORT_PWM0, duty, 40000);
    }
}
```

### 规则引擎 (TDengine 桥接)

规则 SQL (telemetry_bridge):
```sql
SELECT
  payload.illuminance as illuminance,
  payload.temperature as temperature,
  payload.humidity as humidity,
  payload.pm25 as pm25,
  payload.aqi as aqi,
  CASE WHEN payload.pir >= -128 AND payload.pir <= 127 THEN payload.pir ELSE NULL END as pir,
  payload.trafficFlow as traffic_flow,
  now_rfc3339() as ts,
  nth(2, split(topic, '/')) as dev_id
FROM
  "streetlight/+/telemetry"
```

动作 SQL 模板:
```sql
INSERT INTO t_${dev_id} USING telemetry TAGS ('${dev_id}')
VALUES ('${ts}', ${illuminance}, ${temperature}, ${humidity}, ${pm25}, ${aqi}, ${pir}, ${traffic_flow})
```

## 十五、时间戳统一方案

所有时间戳统一为 UTC，前端显示时转为本地时间。

| 来源 | 时间戳格式 | 说明 |
|------|-----------|------|
| 小熊派遥测 | 不含 `collectedAt` | EMQX 规则 `now_rfc3339()` 自动补 UTC 时间 |
| 模拟设备遥测 | `LocalDateTime.now(ZoneOffset.UTC)` | Java UTC |
| TDengine 存储 | UTC 字符串 | `"2026-07-17 05:48:26"` |
| TelemetryDao 查询 | 北京时间 → UTC 字符串 | 传给 TDengine |
| TelemetryDao 读取 | UTC → 北京时间 | 返回前端 |
| 前端显示 | UTC → 本地时区 | `new Date(utcStr + 'Z').toLocaleString('zh-CN')` |

## 十六、故障排查清单

| 现象 | 可能原因 | 检查方法 |
|------|---------|---------|
| 串口输出 "ERROR: No wifi as expected" | 热点关闭或频段不匹配 | 确认手机热点 2.4GHz, 名称密码正确 |
| MQTT 连接成功但无遥测 | MQTTYield 返回值被当作断线 | 检查代码是否忽略 -1 返回值 |
| 命令收不到 | MQTTYield 不工作 | 改用 MQTTSubscribe 重订阅方式 |
| MQTT 鉴权失败 | EMQX 用户不存在 | `GET /api/v5/authentication/.../users` |
| 模拟设备无权连接 | EMQX 用户丢失 | 运行 ResyncAllUsers 工具 |
| EMQX 规则不匹配 | Dashboard 创建 vs API 创建区别 | 必须用 Dashboard 创建规则 |
| Mock 数据降级 | TelemetryDao 时区转换错误 | 检查 UTC 字符串是否正确传给 TDengine |
| 编译失败 | 头文件缺失或常量名错误 | 检查 include 路径和 Hi3861 寄存器名 |
