# 光照阈值配置接口开发日志

完成日期：2026-07-03

## 1. 开发目的

`DecisionEngine` 已支持 `lux_lt` / `lux_gt` 条件判断，但原先只能通过照明策略 CRUD 手动维护 `conditions` JSON。此次新增独立的光照阈值配置 REST API，让前端可以直接读取和设置开灯/关灯光照阈值。

## 2. 本次新增/修改文件

| 文件 | 说明 |
|------|------|
| `src/main/java/com/experiment/smartlightingexp/controller/PolicyController.java` | 新增光照阈值查询和更新接口 |
| `src/main/java/com/experiment/smartlightingexp/dto/LuxThresholdRequest.java` | 新增阈值更新请求 DTO |
| `src/main/java/com/experiment/smartlightingexp/dto/LuxThresholdResponse.java` | 新增阈值查询/更新响应 DTO |
| `docs/API接口文档.md` | 补充光照阈值配置接口说明 |

## 3. 接口总览

| 功能 | 方法 | 路径 | 用途 | 审计 action |
|------|------|------|------|-------------|
| 查询光照阈值 | GET | `/api/policies/lux-threshold` | 获取当前 `lux_lt` / `lux_gt` 配置 | - |
| 更新光照阈值 | PUT | `/api/policies/lux-threshold` | 更新策略 JSON 中的 `lux_lt` / `lux_gt` | `THRESHOLD_SET` |

## 4. GET `/api/policies/lux-threshold`

用途：查询当前光照阈值配置，用于前端阈值设置页面初始化展示。

### 请求字段

无请求参数。

### 成功响应字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `policyId` | Long | 被配置的照明策略 ID |
| `policyName` | String | 策略名称 |
| `luxLt` | BigDecimal | 开灯阈值，DecisionEngine 匹配 `illuminance < lux_lt` |
| `luxGt` | BigDecimal | 关灯阈值，DecisionEngine 匹配 `illuminance > lux_gt` |
| `conditions` | String | 当前策略条件 JSON |
| `enabled` | Boolean | 策略是否启用 |
| `priority` | Integer | 策略优先级 |

### 成功响应示例

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "policyId": 1,
    "policyName": "光照联动自动开关",
    "luxLt": 50,
    "luxGt": 200,
    "conditions": "{\"lux_lt\":50,\"lux_gt\":200}",
    "enabled": true,
    "priority": 1
  }
}
```

### 异常响应

| 场景 | code | msg |
|------|------|-----|
| 未找到未删除的 `THRESHOLD` 策略 | 404 | 光照阈值策略不存在 |
| 策略 `conditions` JSON 无法解析 | 500 | 策略条件 JSON 格式错误 |

## 5. PUT `/api/policies/lux-threshold`

用途：更新光照阈值。接口只改写策略 `conditions` JSON 中的 `lux_lt` / `lux_gt`，保留其他条件字段。

### 请求字段

| 字段 | 类型 | 必填 | 校验 | 说明 |
|------|------|:----:|------|------|
| `luxLt` | BigDecimal | 是 | `>= 0` 且小于 `luxGt` | 开灯光照阈值 |
| `luxGt` | BigDecimal | 是 | `>= 0` 且大于 `luxLt` | 关灯光照阈值 |

### 请求示例

```json
{
  "luxLt": 60,
  "luxGt": 220
}
```

### 成功响应

成功后返回更新后的阈值配置，字段同 GET 接口。

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "policyId": 1,
    "policyName": "光照联动自动开关",
    "luxLt": 60,
    "luxGt": 220,
    "conditions": "{\"lux_lt\":60,\"lux_gt\":220}",
    "enabled": true,
    "priority": 1
  }
}
```

### 异常响应

| 场景 | code | msg |
|------|------|-----|
| `luxLt` 为空 | 400 | luxLt: 开灯光照阈值不能为空 |
| `luxGt` 为空 | 400 | luxGt: 关灯光照阈值不能为空 |
| 阈值小于 0 | 400 | 对应字段不能小于0 |
| `luxLt >= luxGt` | 400 | 开灯光照阈值必须小于关灯光照阈值 |
| 未找到未删除的 `THRESHOLD` 策略 | 404 | 光照阈值策略不存在 |
| 策略 `conditions` JSON 无法解析 | 500 | 策略条件 JSON 格式错误 |

## 6. 数据与审计

- 数据表：`lighting_policy`
- 写入字段：`conditions`
- 更新逻辑：查找未删除、`policy_type = THRESHOLD` 的策略，优先使用包含 `lux_lt` / `lux_gt` 的策略；若存在 THRESHOLD 策略但暂未包含这两个键，则在该策略 JSON 中新增键。
- 审计表：`audit_log`
- 审计 action：`THRESHOLD_SET`
- 审计 target_type：`THRESHOLD`
