## 1. 概述

本文档覆盖智慧路灯节能系统**用户登录与鉴权子系统**的 RESTful API。包括：

- **登录认证**：用户名/密码校验，签发 JWT Token
- **Token 鉴权**：全局 JWT 拦截器，白名单放行登录等公共路径
- **手动控制审计**：从 Token 提取操作人，写入控制指令流水，满足 IR-11 安全可信控制要求

**创新点覆盖：** IR-11（安全可信控制 — 权限校验、操作审计、危险操作确认）

## 2. 全局约定

### 2.1 请求基础地址

```
http://localhost:8080
```

### 2.2 统一响应格式

所有接口统一使用 `Result<T>` 结构返回：

```json
{
  "code": 200,
  "msg": "success",
  "data": { ... }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | int | 状态码，200 成功，其他见错误码说明 |
| `msg` | string | 提示信息 |
| `data` | T | 业务数据载荷 |

### 2.3 鉴权方式

采用 **Bearer Token** 鉴权：

- 登录成功后获取 `token`
- 后续请求在 HTTP Header 中携带：

```
Authorization: Bearer <token>
```

### 2.4 白名单路径（无需登录）

| 路径 | 说明 |
|------|------|
| `POST /api/auth/login` | 用户登录 |
| `/doc.html` | Swagger 文档 |
| `/v3/api-docs` | OpenAPI 文档 |
| `/swagger-resources` | Swagger 资源 |
| `/webjars` | WebJar 资源 |
| `/error` | 错误路径 |
| `/favicon.ico` | 图标 |

## 3. 接口列表

### 3.1 用户登录

- **接口：** `POST /api/auth/login`
- **对应需求：** FR-00（用户登录）、IR-11（审计日志）

**请求参数：**

```json
{
  "username": "admin",
  "password": "admin123"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `username` | string | 是 | 用户名 |
| `password` | string | 是 | 密码（明文） |

**成功响应（200）：**

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "username": "admin",
    "roleCode": "SUPER_ADMIN"
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `token` | string | JWT Token（有效期 24 小时） |
| `username` | string | 用户名 |
| `roleCode` | string | 角色编码，详见角色说明 |

**Token 内部存储信息：**

| Claim | 类型 | 说明 |
|-------|------|------|
| `sub` (subject) | string | 用户名 |
| `roleCode` | string | 角色编码 |
| `permissions` | array[string] | 权限编码列表 |
| `iat` | date | 签发时间 |
| `exp` | date | 过期时间 |

**错误响应（401）：**

```json
{
  "code": 401,
  "msg": "用户名或密码错误",
  "data": null
}
```

**审计日志记录：**

每次登录（成功/失败）均记录审计日志，字段如下：

| 字段 | 值 |
|------|-----|
| `operator` | 请求的用户名 |
| `action` | `LOGIN` |
| `target_type` | `SYSTEM` |
| `detail` | 登录成功-角色:xxx / 登录失败-密码错误 |
| `result` | `SUCCESS` / `FAIL` |
| `ip_address` | 客户端 IP |

### 3.2 获取当前用户信息

- **接口：** `GET /api/auth/me`
- **用途：** 前端校验 Token 有效性、获取当前登录用户信息

**请求头：**

```
Authorization: Bearer <token>
```

**成功响应（200）：**

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "username": "admin",
    "roleCode": "SUPER_ADMIN"
  }
}
```

**错误响应（401）：**

```json
{
  "code": 401,
  "msg": "未登录或 Token 无效",
  "data": null
}
```

### 3.3 手动控制设备

- **接口：** `POST /api/devices/{deviceId}/control`
- **对应需求：** FR-05（手动远程控制）、IR-11（安全可信控制 — 操作审计）

**请求头：**

```
Authorization: Bearer <token>
Content-Type: application/json
```

**路径参数：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `deviceId` | string | 是 | 设备编号（如 SL-001） |

**请求体：**

```json
{
  "action": "ON",
  "brightness": null
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `action` | string | 是 | 指令类型：`ON`（开灯）、`OFF`（关灯）、`DIMMING`（调光） |
| `brightness` | int | DIMMING 时必填 | 亮度 0-100 |

**校验规则：**

- `deviceId` 对应的设备必须存在
- `action` 仅支持 `ON` / `OFF` / `DIMMING`
- `DIMMING` 指令必须提供 `brightness`（0-100）

**成功响应（200）：**

```json
{
  "code": 200,
  "msg": "success",
  "data": null
}
```

**错误响应示例：**

```json
{
  "code": 500,
  "msg": "设备不存在",
  "data": null
}
```

**接口内部流程：**

1. 从 `SecurityContext`（由 JWT 拦截器注入）获取当前用户名
2. 组装 MQTT 指令载荷（含 `action`, `issuedAt`, `source: "MANUAL"`, `operator`）
3. 发布 MQTT 消息到 `streetlight/{deviceId}/command`
4. 记录 `control_command` 流水表，`operator` 字段记录操作人
5. 更新设备 `last_manual_at` 时间戳（AI 策略引擎在 30 分钟内跳过此设备）

**审计追溯（IR-11）：**

`control_command` 表中每条记录包含：

| 字段 | 值示例 | 说明 |
|------|--------|------|
| `operator` | `admin` | 操作人用户名（从 Token 提取） |
| `action` | `ON` / `DIMMING(70)` | 指令内容 |
| `source` | `MANUAL` | 指令来源 |
| `status` | `SENT` | 指令状态 |
| `issued_at` | `2026-07-02T10:30:00` | 指令下发时间 |

## 4. 数据模型

### 4.1 `LoginRequest` — 登录请求

| 字段 | 类型 | 校验 | 说明 |
|------|------|------|------|
| `username` | string | @NotBlank | 用户名 |
| `password` | string | @NotBlank | 密码 |

### 4.2 `LoginResponse` — 登录响应

| 字段 | 类型 | 说明 |
|------|------|------|
| `token` | string | JWT Token |
| `username` | string | 用户名 |
| `roleCode` | string | 角色编码 |

### 4.3 `ControlRequest` — 控制请求

| 字段 | 类型 | 校验 | 说明 |
|------|------|------|------|
| `action` | string | @NotBlank | ON / OFF / DIMMING |
| `brightness` | Integer | @Min(0) @Max(100) | 调光亮度 |

### 4.4 `Result<T>` — 统一响应

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | int | 状态码 |
| `msg` | string | 提示信息 |
| `data` | T | 业务数据 |

### 4.5 `SecurityContext` — 安全上下文

| 方法 | 返回类型 | 说明 |
|------|----------|------|
| `getCurrentUsername()` | String | 获取当前用户名 |
| `getCurrentRole()` | String | 获取当前角色编码 |
| `getCurrentPermissions()` | List\<String\> | 获取权限列表 |
| `hasPermission(code)` | boolean | 判断是否拥有某权限 |
| `getCurrentUser()` | UserInfo | 获取完整用户信息 |

## 5. 错误码说明

| 状态码 | 说明 | 典型场景 |
|--------|------|----------|
| `200` | 成功 | 请求处理成功 |
| `400` | 参数错误 | 请求参数校验失败 |
| `401` | 未登录 / Token 无效 | 未携带 Token、Token 过期、用户名密码错误 |
| `500` | 服务器内部错误 | MQTT 下发失败、角色配置异常 |

## 6. 数据库表结构

### 6.1 `user` — 用户表

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT | 主键，自增 |
| `username` | VARCHAR(50) | 用户名，唯一 |
| `password` | VARCHAR(255) | 密码 |
| `real_name` | VARCHAR(50) | 真实姓名 |
| `role_id` | BIGINT | 角色 ID，外键关联 `role` 表 |
| `enabled` | TINYINT(1) | 是否启用（0=禁用，1=启用） |
| `create_time` | DATETIME(3) | 创建时间 |
| `update_time` | DATETIME(3) | 更新时间 |

### 6.2 `role` — 角色表

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT | 主键，自增 |
| `name` | VARCHAR(50) | 角色名称 |
| `role_code` | VARCHAR(20) | 角色编码，唯一 |
| `description` | VARCHAR(255) | 角色描述 |
| `create_time` | DATETIME(3) | 创建时间 |

### 6.3 `permission` — 权限表

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT | 主键，自增 |
| `name` | VARCHAR(50) | 权限名称 |
| `permission_code` | VARCHAR(50) | 权限编码，唯一 |
| `description` | VARCHAR(255) | 权限描述 |
| `create_time` | DATETIME(3) | 创建时间 |

### 6.4 `role_permission` — 角色权限关联表

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT | 主键，自增 |
| `role_id` | BIGINT | 角色 ID |
| `permission_id` | BIGINT | 权限 ID |
| 唯一约束 | `(role_id, permission_id)` | 保证不重复分配 |

## 附录：快速测试

### curl 测试示例

```bash
# 1. 登录
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}'

# 2. 获取当前用户信息
curl http://localhost:8080/api/auth/me \
  -H "Authorization: Bearer <token>"

# 3. 手动开灯
curl -X POST http://localhost:8080/api/devices/SL-001/control \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"action":"ON"}'

# 4. 手动调光至 70%
curl -X POST http://localhost:8080/api/devices/SL-001/control \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"action":"DIMMING","brightness":70}'
```
