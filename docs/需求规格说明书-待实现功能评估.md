## 三、待实现功能详细说明

### 1. IR-05 / IN-04 视觉感知事件 ✅ 已完成 (07-04)

**现状：**

- `vision_event` 表、`VisionEvent` entity、`VisionEventMapper`、`VisionEventService` 已建好
- **缺 `VisionEventController`** — 没有任何 REST API
- 前端无任何视觉事件展示页面
- MockDataGenerator 未生成视觉事件模拟数据

**需实现：**

| 层级 | 内容 |
|------|------|
| 后端 Controller | `VisionEventController`：分页查询 `GET /api/vision-events/page`、按设备查询、事件录入 `POST /api/vision-events` |
| 后端模拟 | `MockDataGenerator` 增加视觉事件生成（随机产生行人/车辆/异常停车等事件，发布到 `streetlight/{deviceId}/vision/event`） |
| 后端订阅 | `MqttSubscriber` 订阅 `vision/event` topic，写入 `vision_event` 表，联动生成 AlarmRecord |
| 前端页面 | 新增"视觉事件"Tab 或在告警页面展示（事件类型、置信度、截图引用、发生时间） |

**工作量估算：** 约 1 天

**vision_event 表结构：**
```
id, deviceId, eventType(行人/车辆/异常停车/危险场景),
confidence(置信度), snapshotRef(截图引用), occurredAt, createTime
```

### 3. IR-07 / IN-06 预测性维护与健康评分 ✅ 已完成 (07-04)

**现状：**

- `device.health_score` 字段存在但**始终为 NULL**，从未被写入
- 无任何健康评分计算逻辑
- 无维护建议生成逻辑

**需实现：**

| 层级 | 内容 |
|------|------|
| 后端定时任务 | `HealthScoreTask`（每天凌晨执行），综合以下维度计算 0-100 分： |
|  | ① 离线频次：近 7 天 `alarm_record` 离线次数（权重 30%） |
|  | ② 通信质量：近 24h 遥测上报间隔标准差（权重 25%） |
|  | ③ 指令响应率：`control_command` SENT/ACK 成功率（权重 25%） |
|  | ④ 传感器异常率：遥测字段为 null 或超出合理范围的占比（权重 20%） |
| 后端 API | `GET /api/devices/{deviceId}/health` 返回评分 + 各维度明细 + 下降原因 |
|  | `GET /api/devices/health/summary` 返回所有设备健康概览 |
| 前端 | `DeviceDetail` 增加健康评分卡片（环形进度条 + 分维度雷达图） |
|  | `DeviceList` 增加健康状态筛选和排序 |

**工作量估算：** 约 2 天

### 7. IN-02 边缘AI决策模拟 ✅ 已完成 (07-05)

**已实现：**

| 层级 | 内容 |
|------|------|
| 引擎 | `ConditionEvaluator` — 纯函数工具类（零 Spring 依赖），将条件评估逻辑从 DecisionEngine 抽离，云端和边缘共享同一套判断代码 |
| 后端 | `EdgeNodeSimulator` 定时任务（60s 周期）：随机选 5 台在线设备作为"边缘节点" → 读取策略缓存 + 最新遥测 → ConditionEvaluator 本地评估 → 写入 decision_log（EDGE_MATCH_EXECUTED / EDGE_NO_MATCH） |
| 后端 API | `GET /api/dashboard/edge-status` — 返回边缘决策总数、命中数、最近模拟时间 |
| 前端 | Dashboard 顶部统计卡片新增"边缘AI决策"（命中次数实时展示） |

**真实硬件迁移路径：**
ConditionEvaluator 无任何 Spring 依赖，仅需 `Map` + `BigDecimal` + JSON 解析器 → 可直接编译部署到边缘网关（如树莓派/ESP32 上的 Java/Kotlin 运行时），与云端使用完全一致的评估逻辑。

**决策：已完成**
