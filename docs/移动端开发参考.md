#### natapp 域名说明及移动端处理方式

**域名变化场景**：
- natapp 终端保持运行 → 域名不变
- 短暂断网 → 通常自动重连，域名不变
- `Ctrl+C` 关闭 / 重启 natapp / 电脑重启 → **域名大概率会变**

**移动端处理方式**：将接口基地址定义为一个全局常量，所有请求从这个常量拼路径，域名变了只改一行：

```dart
// Flutter
const BASE_URL = '{{BASE_URL}}';
```

```java
// Android
public static final String BASE_URL = "{{BASE_URL}}";
```

```swift
// iOS
let BASE_URL = "{{BASE_URL}}"
```

```javascript
// React Native
const BASE_URL = '{{BASE_URL}}';
```

域名变化时修改这一处即可，无需全局搜索替换。

> 💡 域名如发生变化，联系后端获取最新地址，更新本地 BASE_URL 常量后重新编译/热重载即可。

## 二、认证方式

所有业务接口（白名单除外）需要在请求头携带 JWT Token。

### 登录

```
POST /api/auth/login
Content-Type: application/json

{
  "username": "admin",
  "password": "admin123"
}
```

返回 `data.token`，后续请求带上：

```
Authorization: Bearer <token>
```

### 测试账号

| 用户名 | 密码 | 角色 |
|--------|------|------|
| `admin` | `admin123` | SUPER_ADMIN（全权限） |

### Token 有效期

24 小时（86400000ms），过期需重新登录。

### 白名单路径（无需 Token）

- `/api/auth/login` — 登录
- `/doc.html` — 接口文档
- `/v3/api-docs/**`、`/swagger-resources/**`、`/webjars/**` — Swagger 资源

## 六、接口通用规范

- **统一响应格式**：
  ```json
  { "code": 200, "msg": "success", "data": {...} }
  ```
- **分页请求**（`/list` 接口）：`{ "page": 1, "size": 10, ...查询条件 }`
- **分页响应**：`{ "records": [...], "total": 100, "size": 10, "current": 1 }`
- **错误码**：`401` 未登录/Token过期，`403` 无权限，业务错误在 `msg` 中说明

## 七、常见问题

1. **接口调不通？** → 确认开发机后端 + natapp 都在运行中
2. **返回 401？** → Token 过期，重新调登录接口获取新 Token
3. **返回 403？** → 接口需要特定权限，确认账号角色是否有该权限码
4. **natapp 地址变了？** → 联系后端重新确认地址
