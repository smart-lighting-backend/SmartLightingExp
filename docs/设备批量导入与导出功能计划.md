# 设备批量导入与导出功能计划

## 一、Bug 修复：手动控制关闭按钮卡死

**文件**: `src/components/ManualControlModal.vue:80-85`

**问题**:
```js
function closeModal() {
  if (hasChanges.value) {
    window.location.reload()
  } else {
    closeModal()  // BUG: 无限递归，应改为 emit('close')
  }
}
```

`closeModal()` 在 `hasChanges=false` 时调用自身，导致无限递归，页面卡死。`hasChanges=true` 时直接 `window.location.reload()` 也过于粗暴。

**修复**:
```js
function closeModal() {
  emit('close')
}
```

每条指令已实时通过 MQTT 下发，无需"保存"操作，关闭即可。

## 二、批量导入功能

### 概述

市政路灯动辄数百上千盏，逐条录入不现实。通过 Excel 文件批量导入。

### 流程

```
① 用户点击"批量导入" → 弹窗 → 点击"下载模板" → 得到 .xlsx 空模板
② 用户在 Excel/WPS 中打开模板，逐行填写设备信息，保存
③ 回到系统，点击或拖拽上传填好的 .xlsx/.csv 文件
④ 系统解析 → 逐行校验 → 预览表格（错误行红色标记 + 原因）
⑤ 确认无误 → 点击"确认导入"
⑥ 后端批量写入 → 返回：成功 48 条，失败 2 条（显示失败详情）
```

> 用户不需要在网页上在线编辑表格。模板下载到本地 → Excel 填好 → 上传回来，三步即可。

### 模板设计

模板文件由前端直接生成（Blob 下载），无需后端参与：

| 列 | 字段 | 必填 | 校验规则 | 示例 |
|----|------|------|---------|------|
| 设备编号 | deviceId | **是** | 最长50字符，不可重复 | SL-007 |
| 设备名称 | name | 否 | — | 北门-03 |
| 所属区域 | area | 否 | — | A区 |
| 经度 | longitude | 建议 | 73.5~135（中国境内） | 106.5622 |
| 纬度 | latitude | 建议 | 18~54（中国境内） | 29.5621 |
| 额定功率(W) | ratedPower | 否 | >0 | 60 |

### 前端实现

| 步骤 | 说明 |
|------|------|
| 1. 模板下载 | `xlsx` 库生成含表头的空工作簿，`saveAs` 下载 |
| 2. 文件上传 | `<input type="file" accept=".xlsx,.csv">` 或拖拽 |
| 3. 解析 | `XLSX.read()` → `XLSX.utils.sheet_to_json()` |
| 4. 逐行校验 | deviceId 必填/格式/重复（已有设备 + 本文件内重复）；经纬度范围 |
| 5. 预览表格 | Element Plus `ElTable`，错误行标红 + tooltip 原因，正确行正常显示 |
| 6. 确认导入 | 调用 `POST /api/devices/batch`，携带 `{ devices: [...] }` |
| 7. 结果展示 | `ElMessage`：成功 X 条 / 失败 Y 条，失败列表展开查看 |

### 后端新增

| 项目 | 说明 |
|------|------|
| 接口 | `POST /api/devices/batch` |
| Controller | `DeviceController.batchCreate(@RequestBody List<DeviceCreateRequest>)` |
| 参数校验 | `@Valid` + Jakarta Validation |
| 事务 | `@Transactional` — 默认全部成功或全部回滚 |
| 响应 | `{ total: 50, success: 48, failed: [{ row:3, deviceId:"SL-007", reason:"设备编号重复" }] }` |
| 权限 | `@RequirePermission("device:create")` |

### 依赖

| 层 | 库 | 用途 |
|----|-----|------|
| 前端 | `xlsx` (SheetJS, ~100KB) | 模板生成 + 文件解析 |

## 三、设备导出功能

### 概述

按区域导出设备基本信息为 Excel 文件，方便运维人员离线查看、打印、汇报。

### 流程

```
设备管理页 → 点击"导出"按钮
  → 下拉菜单：导出全部 / 按区域导出（A区 / B区 / C区……）
  → 前端 fetch 设备数据 → xlsx 生成文件 → 浏览器下载
```

### 导出字段

| 列 | 字段 | 说明 |
|----|------|------|
| 设备编号 | deviceId | — |
| 设备名称 | name | — |
| 所属区域 | area | — |
| 安装位置 | location | 经纬度字符串 |
| 状态 | status | 在线/离线/异常/停用 |
| 健康分 | healthScore | 0~100 |
| 额定功率(W) | ratedPower | — |
| 是否启用 | enabled | 是/否 |
| 最后心跳 | lastHeartbeatAt | 格式化时间 |
| 订阅前缀 | topicPrefix | — |

### 实现方案：纯前端

无需后端改动。复用现有 `fetchDeviceList` 取全量设备，`xlsx` 生成文件，`saveAs` 触发下载。

| 步骤 | 说明 |
|------|------|
| 1. 获取数据 | 按区域筛选调用 `fetchDeviceList({ area })` 或取全部 |
| 2. 转换 | 状态码 → 中文（1→在线、2→离线…）；布尔 → 是/否 |
| 3. 时间格式化 | `lastHeartbeatAt` ISO → `2026-07-05 14:30` |
| 4. 生成 | `XLSX.utils.json_to_sheet()` → `XLSX.utils.book_new()` |
| 5. 下载 | `XLSX.writeFile(wb, '设备清单_A区.xlsx')` |

### 可行性评估

| 维度 | 评估 |
|------|------|
| 技术可行性 | **高** — 纯前端实现，无后端依赖 |
| 用户价值 | **高** — 运维/汇报/盘点刚需 |
| 复杂度 | **低** — xlsx 库同时用于导入和导出，复用 |
| 权限 | 复用 `device:read` |

### 扩展可能

- 导出格式可选 CSV（兼容老旧系统）
- 支持导出筛选结果（当前搜索+状态过滤后的设备）
- 支持导出含遥测数据快照的完整报表
