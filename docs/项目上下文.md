# 项目上下文

## 项目背景

智慧路灯实验项目，基于重庆交通大学与中软国际人才培养集中实训方案，构建一套面向市政道路照明的物联网管理系统。通过传感器采集环境数据、MQTT 远程通信、后端自动策略控制，实现路灯的智能开关、调光、告警与数据分析。

## 关键业务流程

1. **遥测数据采集**: 设备/模拟器通过 MQTT 发布到 `streetlight/{deviceId}/telemetry` → MqttSubscriber 写入 telemetry 表，同时更新设备心跳和最新数据快照
2. **AI 自动控制**: 每次收到遥测后触发 DecisionEngine，读取启用的照明策略，按优先级匹配条件，命中后下发 MQTT 控制指令并记录 decision_log
3. **心跳离线检测**: HeartbeatMonitorTask 每 60s 扫描一次，检测超时（默认 300s）未上报的设备，标记离线并生成告警；设备重新上报时自动恢复告警
4. **能耗统计**: EnergyCalcTask 每日 23:55 执行，读取当日 control_command 记录，按时间加权平均亮度计算节能率、用电量和碳减排量，upsert 写入 energy_record
5. **手动锁定**: 手动操作后 30 分钟内（MANUAL_LOCK_MINUTES=30），AI 策略引擎跳过该设备，防止自动策略覆盖人工干预
6. **认证鉴权**: JWT 拦截器校验所有请求（白名单除外），解析用户/角色/权限注入 SecurityContext ThreadLocal，请求结束自动清除

## 节能率（Energy Saving Rate）

### 定义
节能率 = (基准能耗 - 实际能耗) / 基准能耗 × 100%

- **基准能耗**：不采用任何节能策略时的理论能耗（即 100% 亮度全天亮灯）
- **实际能耗**：经过自适应调光、按需照明等策略控制后的实际用电量
- 数据存储在 `energy_record.saving_rate` 字段（DECIMAL(5,2)，百分比）

### 数据库结构

`energy_record` 表（日粒度设备级能耗统计）:
| 字段 | 类型 | 说明 |
|------|------|------|
| `device_id` | VARCHAR(50) | 设备ID |
| `record_date` | DATE | 统计日期 |
| `on_duration_min` | INT | 亮灯时长（分钟） |
| `avg_brightness` | DECIMAL(5,2) | 平均亮度（0~100） |
| `estimated_kwh` | DECIMAL(10,4) | 估算用电量（千瓦时） |
| **`saving_rate`** | **DECIMAL(5,2)** | **节能率（%）** |
| `carbon_reduction` | DECIMAL(10,4) | 碳减排估算（kg CO₂） |

### 当前后端计算逻辑

- **节能率**: `DashboardController.stats()` — 查询当日所有 energy_record，对 saving_rate 求均值
- **写入**: EnergyCalcTask 每日 23:55 自动执行，遍历已启用设备，读取当日 control_command 中 DIMMING 指令的亮度值，按时间加权计算平均亮度，推算用电量/节能率/碳减排，upsert 写入 energy_record
- **无调光指令时**: 默认 avg_brightness = 100%（节能率 0%），避免虚报

### 前端显示
- **Dashboard 仪表盘**：顶部统计卡片显示 `energySavingRate` + "%"，Mock 默认值 32.5%
- **数据报表页（Analytics.vue）**：展示年度总能耗、年度节省量、碳减排量、月度能耗对比柱状图、分区能耗占比饼图

## 设备分区（Area / 区域）

### 定义
设备通过 `device.area` 字段（VARCHAR(50)）标识所属区域，是设备台账的基础属性。区域是设备的**逻辑分组**，维度上描述设备的地理或管理归属。

### 数据库
```sql
area VARCHAR(50) DEFAULT NULL COMMENT '区域（如：A区、B区）'
```
- 有独立索引 `KEY idx_area (area)`
- 区域内可包含多个设备

### 后端分区统计
`DashboardController.districts()` — 按 `area` 字段分组统计各区域设备的在线/离线/告警数量。

### 前端分区显示方式

| 页面 | 显示方式 | 数据来源 |
|------|---------|---------|
| **Dashboard 仪表盘** | 右侧"分区设备状态"卡片：列表显示每个区域名称 + 在线/离线/告警数量 + 在线率进度条 | `GET /api/dashboard/districts` |
| **设备管理列表** | 设备表格中的"区域"列，支持按区域关键词搜索过滤 | `POST /api/devices/list` 中 `area` 参数 |
| **数据报表页** | 饼图展示分区能耗占比 | Mock 数据（高新区、市中心、工业园、学院路等） |

### Mock 示例区域值
- **后端 Mock**: A区, B区, C区, D区, E区
- **前端 Mock (dashboard.js)**: 高新区, 创业园区, 市中心, 工业园, 学院路段
- **前端 Mock (Analytics.vue 饼图)**: 高新区(32), 市中心(25), 工业园(20), 学院路(13), 其他(10)
