# 并发优化备忘

> 2026-07-13 全项目并发评估产出。当前阶段（20 台设备、单用户）暂不触发，设备量/用户量增长后逐项修复。

---

## 一、已修复

### P0 — MqttPublisher 线程池无界

- **文件**：`MqttPublisher.java`
- **问题**：`Executors.newCachedThreadPool()` 无上限，高并发下可能无限创建线程导致 OOM
- **修复**：改为 `Executors.newFixedThreadPool(8)`
- **commit**：`6ece512`

---

## 二、待设备量/用户量增长后修复

### P1 — 遥测写入竞态

- **文件**：`MqttSubscriber.java:125-163`
- **现象**：16 线程池处理遥测，同一设备的两条消息可能被两个线程同时处理，latestData 快照可能丢更新
- **当前为何不触发**：MockDataGenerator 每 60s 发 1 条全字段遥测，同设备消息间隔远大于处理耗时
- **触发条件**：设备端改为高频上报（≤5s 间隔）或分批发送不同传感器数据
- **修复方案**：在 device 表加 `version` 字段（乐观锁），UPDATE 时校验 `WHERE version = ?`，CAS 失败则重试
- **替代方案**：UPDATE 时加时间戳条件 `WHERE lastHeartbeatAt < ?`，只有比我旧的才更新

### P2 — 定时任务线程池不足

- **文件**：`application.yaml:8` — `spring.task.scheduling.pool.size: 4`
- **现象**：8 个 `@Scheduled` 任务共享 4 线程，高峰期 MockGen(2) + Heartbeat(1) + HealthScore(1) 同窗口触发时可能排队
- **当前为何不触发**：设备少（21台），每个任务耗时极短（<1s-10s），4 线程很少同时被占满
- **触发条件**：设备量 ≥100 台、或去掉 mock 改为真实设备高频上报
- **修复方案**：`pool.size` 从 4 改为 8

### P3 — TDengine 连接池偏小

- **文件**：`TdengineConfig.java:18` — `maximumPoolSize = 5`
- **现象**：16 个 MQTT 处理线程 + Web 请求共享 5 个 TDengine 连接
- **当前为何不触发**：遥测写入走 EMQX 规则引擎直连 TDengine，不经过后端连接池；后端只做查询，单用户同一时刻 1-2 个查询
- **触发条件**：多用户同时查设备详情/历史趋势、或 Dashboard 高频刷新
- **修复方案**：`maximumPoolSize` 从 5 改为 10-15

### P4 — 心跳/遥测/离线检测三路状态更新冲突

- **文件**：`MqttSubscriber.java`（心跳/遥测）、`HeartbeatMonitorTask.java`
- **现象**：心跳处理在 MQTT 回调线程、遥测处理在 16 线程池、离线检测在定时任务线程，三路都在更新 `device.status` 和 `lastHeartbeatAt`，时间竞态可能误判离线
- **触发条件**：网络抖动导致心跳延迟 + 离线检测恰好触发
- **修复方案**：
  - 统一写入路径：心跳和遥测只更新 `lastHeartbeatAt`，状态判定全交给 `HeartbeatMonitorTask`
  - 或：离线检测时加缓冲容差（当前用 `elapsedSeconds < threshold` 已具备基本防护）

### P5 — 遥测处理链路无事务

- **文件**：`MqttSubscriber.java:125-166`
- **现象**：遥测处理涉及 device 更新 + TDengine 写入 + FAULT 告警创建，无事务边界，中间步骤失败不回滚
- **触发条件**：任一写入步骤失败（如 TDengine 连接超时、MySQL 唯一约束冲突）
- **修复方案**：评估是否真的需要跨库事务——通常不需要，因为 TDengine 写入由 EMQX 桥接保证，后端只需保证 device 更新和告警创建的一致性。可对这两个 MySQL 操作加 `@Transactional`

## 三、当前并发架构快照

| 层级 | 配置 | 备注 |
|------|------|------|
| Tomcat Web 线程 | 默认 200 | `server.tomcat.threads.max` 未显式配置 |
| MySQL 连接池 | HikariCP max=30, min=10 | `application.yaml` spring.datasource.hikari |
| TDengine 连接池 | HikariCP max=5, min=1 | `TdengineConfig.java` |
| MQTT 遥测处理 | 16 线程 FixedPool | `MqttSubscriber.executor` |
| MQTT 发布 | 8 线程 FixedPool（已修） | `MqttPublisher.publishExecutor` |
| 定时任务调度 | 4 线程 | `spring.task.scheduling.pool.size` |
| MQTT 连接 | Paho 单连接, maxInflight=50 | `MqttConfig.java` |
| EMQX | 单节点 Docker, Enterprise 6.2.1 | 当前 tcp:1883 1 连接（后端） |

## 四、扩容路径建议

```
当前（20台/60s）→ 无需改动
        ↓
100台/30s  → P2(线程池)、P3(TDengine连接池)
        ↓
500台/10s  → P1(乐观锁)、P4(状态统一写入)、P5(事务)
        ↓
1000台+/5s → 考虑 EMQX 集群 + MySQL 读写分离 + TDengine 集群
```
