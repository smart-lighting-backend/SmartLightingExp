# 后端待办 — 分区统计修复（等待前端伙伴确认后再实施）

> 创建日期：2026-07-03
> 背景：Dashboard 分区设备状态卡片发现统计缺口 —— status=0（停用）的设备未计入任何分类，area=NULL 的设备也未归属到任何分区。
> 以下改动需要等前端伙伴确认当前分支修改范围后再进行。

## 1. DashboardController.districts() — 修复统计缺口

- **现状**：只统计了 status=1（在线）、2（离线）、3（异常），status=0（停用）的设备被静默忽略
- **预期**：增加 status=0 的统计，作为 `disabled`（停用）字段返回，让每个分区的设备数能对上总设备数

**涉及的代码位置**：`DashboardController.java:156-186`，`districts()` 方法

```java
// 修改前
long online  = list.stream().filter(d -> d.getStatus() != null && d.getStatus() == 1).count();
long offline = list.stream().filter(d -> d.getStatus() != null && d.getStatus() == 2).count();
long warning = list.stream().filter(d -> d.getStatus() != null && d.getStatus() == 3).count();

// 修改后 — 增加停用设备统计
long online   = list.stream().filter(d -> d.getStatus() != null && d.getStatus() == 1).count();
long offline  = list.stream().filter(d -> d.getStatus() != null && d.getStatus() == 2).count();
long warning  = list.stream().filter(d -> d.getStatus() != null && d.getStatus() == 3).count();
long disabled = list.stream().filter(d -> d.getStatus() != null && d.getStatus() == 0).count();
```

## 2. 处理 area 为 NULL 的设备

- **现状**：`filter(d -> d.getArea() != null && !d.getArea().isBlank())` 直接排除了无区域设备
- **预期**：area 为 NULL 或空字符串的设备归入 `"未分配"` 分区，而不是消失

## 3. 返回字段变更

`GET /api/dashboard/districts` 的每个分区对象新增字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | String | 区域名称（或"未分配"） |
| `online` | long | 在线设备数 |
| `offline` | long | 离线设备数 |
| `warning` | long | 异常设备数 |
| **`disabled`** | **long** | **停用设备数（新增）** |

## 4. 关于分页的评估结论

- **不做分页**：Dashboard 是概览页，分区卡片作为右侧辅助信息，加分页破坏"一屏可见性"
- 实际路灯项目分区通常不超过 10-20 个，当前内存分组方式够用
- 若未来分区数过多，改为 `GROUP BY area` SQL 查询 + 限制 TOP N 区域，超出部分归入"其他"
