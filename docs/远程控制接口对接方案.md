# 远程控制接口对接方案

## 1. 背景

DeviceDetail.vue 的远程控制面板目前完全依赖 `api/control.js` 的纯前端 Mock 实现，未与后端 `ControlController` 建立真实通信。需要将控制指令对接至后端真实接口，同时保留 Mock 降级能力。

## 2. 现状分析

### 2.1 前端现状（api/control.js）

- `sendControlCommand(deviceId, command, params)` — 已重构为 safeCall 模式
- `getControlHistory(deviceId, page, pageSize)` — 已重构为 safeCall 模式
- 支持的指令：`turn_on`, `turn_off`, `dim`, `flash`, `restart`
- 期望的响应格式：

```json
{
  "code": 200,
  "message": "开灯指令已下发",
  "data": {
    "deviceId": "SL-001",
    "command": "turn_on",
    "params": {},
    "feedback": {
      "status": "success",
      "message": "设备已响应，灯光已开启",
      "executed_at": "2026-07-03 14:35:00"
    }
  }
}
```

### 2.2 后端现状（ControlController）

- 端点：`POST /api/devices/{deviceId}/control`
- 请求体：`{ action: "ON"|"OFF"|"DIMMING", brightness?: number }`
- 返回格式：`Result<Void>` = `{ code, msg, data: null }`
- 流程：校验 → 发 MQTT → 记录 control_command（status="SENT"）→ 更新 lastManualAt → 返回
- 有效指令：`ON`, `OFF`, `DIMMING`
- **不支持**：`flash`, `restart`

### 2.3 新增后端接口

- `GET /api/devices/{deviceId}/control-history?page=1&size=10`
- 复用 control_command 表，按 issued_at 倒序分页
- 返回 `Result<Page<ControlCommand>>`

## 3. 差距分析

| 对比项 | 前端要求 | 后端提供 | 差距 |
|--------|----------|----------|------|
| 动作命名 | `turn_on` / `turn_off` / `dim` | `ON` / `OFF` / `DIMMING` | 命名不匹配，前端 API 层映射 |
| 额外动作 | `flash`, `restart` | 无 | 保留纯 Mock |
| 响应结构 | `data.feedback.status/message/executed_at` | `data: null` | 前端 API 层适配 |
| 执行反馈 | 设备执行结果 + 时间戳 | MQTT 仅下发，无异步回执跟踪 | 硬件阶段补充 |
| 历史记录 | `getControlHistory(deviceId)` | 已新增查询接口 | 已对接 |

## 4. 改造方案

### 4.1 方案要点

1. **命令映射表**：`turn_on→ON`, `turn_off→OFF`, `dim→DIMMING`
2. **safeCall 模式**：接入真实 HTTP 调用，后端不可达时降级 Mock
3. **Mock 保留**：`flash`, `restart` 纯 Mock；`turn_on`, `turn_off`, `dim` 走后端
4. **响应适配**：后端 `{ code, msg }` → 前端 `{ code, data: { deviceId, command, params, feedback } }`
5. **历史记录**：新增 `GET /api/devices/{deviceId}/control-history`，复用 control_command 表

### 4.2 改造范围

| 文件 | 改动 |
|------|------|
| `api/control.js` | 重构为 safeCall 模式，命令映射，响应适配 |
| `api/control.js` | flash/restart 保留 Mock，其余走后端 |
| `ControlController.java` | 新增 controlHistory 查询端点 |

### 4.3 不修改的部分

- DeviceDetail.vue：调用方不变，`sendControlCommand` 签名保持不变
- ControlController.java 核心逻辑：校验/MQTT下发/审计日志 不动
- 路由：无需新增

## 5. 决策记录（2026-07-03）

| 决策项 | 决定 | 理由 |
|--------|------|------|
| flash/restart 后端支持 | **暂不支持**，保留纯 Mock | 硬件板尚未接入，T/ZGCSC 012-2024 标准支持 restart，硬件阶段按需开启 |
| 控制历史后端接口 | **已实现** | control_command 表已有数据，后端新增 GET 查询端点 |
| MQTT 执行回执跟踪 | **硬件阶段实现** | 当前为软件联调阶段，硬件（华为基地实训）支持后再补充 MQTT 消费者更新 ack_at |
