
这些接口用于支撑前端：

- 显示路灯基本信息。
- 展示设备健康分和状态。
- 按区域、状态搜索和过滤设备。
- 展示实时遥测卡片。
- 使用 ECharts 绘制历史趋势图。



## 2. 已实现接口总览

| 接口 | 方法 | 用途 | 返回/行为 |
|---|---|---|---|
| `/api/devices/list` | GET | 设备台账列表 | 返回所有未删除设备，含健康分、状态、最新数据，支持 `area/status` 过滤 |
| `/api/devices/{deviceId}` | GET | 单设备详情 | 按 `deviceId` 查询设备，未找到返回 `404` |
| `/api/telemetry/latest/{deviceId}` | GET | 实时卡片数据 | 返回该设备最新一条遥测记录，未找到返回 `404` |
| `/api/telemetry/history` | POST | 历史趋势图 | 接收 `deviceId/startTime/endTime`，返回按 `collectedAt` 升序排列的数据 |
| `/api/devices/statistics/status` | GET | 状态统计 | 按状态分组统计设备数量，支持按区域过滤 |
| `/api/devices/statistics/area-status` | GET | 区域状态统计 | 按 `area + status` 分组统计设备数量 |

## 3. 接口请求字段与成功响应

以下接口均以本地开发环境为例：

```text
http://localhost:8080
```

响应字段采用项目实体类的驼峰命名方式，时间字段为 ISO-8601 风格字符串。

### 3.1 GET `/api/devices/list`

用途：返回设备台账列表，支持前端按区域和状态过滤，用于路灯基础信息列表和搜索结果。

#### 请求字段

| 字段 | 位置/类型 | 是否必填 | 说明 |
|---|---|---|---|
| `area` | Query / String | 否 | 区域过滤条件，例如 `A`、`B`、`C` 或数据库中实际区域值。不传时查询全部区域。 |
| `status` | Query / Integer | 否 | 设备状态过滤条件：`0` 停用，`1` 在线，`2` 离线，`3` 异常。不传时查询全部状态。 |

#### 成功响应

HTTP 200，返回设备数组。数组元素主要字段如下：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | Long | 数据库主键 |
| `deviceId` | String | 设备唯一编号，例如 `SL-001` |
| `name` | String | 设备名称 |
| `area` | String | 所属区域 |
| `location` | String | 安装位置或经纬度描述 |
| `status` | Integer | 设备状态：`0` 停用，`1` 在线，`2` 离线，`3` 异常 |
| `healthScore` | Decimal | 健康分，前端可用于健康状态展示 |
| `topicPrefix` | String | MQTT 主题前缀 |
| `lastHeartbeatAt` | DateTime | 最后心跳时间 |
| `latestData` | String/JSON | 设备最新遥测快照，来自 `device.latest_data` |
| `enabled` | Boolean | 是否启用 |
| `deleted` | Boolean | 是否逻辑删除 |

#### 请求示例

```http
GET /api/devices/list?area=A&status=1
```

#### 成功响应示例

```json
[
  {
    "id": 1,
    "deviceId": "SL-001",
    "name": "南门-01",
    "area": "A",
    "location": "106.5622,29.5621",
    "status": 1,
    "healthScore": 98.50,
    "topicPrefix": "streetlight",
    "lastHeartbeatAt": "2026-07-02T09:18:06",
    "latestData": "{...}",
    "enabled": true,
    "deleted": false
  }
]
```

### 3.3 GET `/api/telemetry/latest/{deviceId}`

|---|---|---|---|
| `deviceId` | Path / String | 是 | 设备唯一编号，例如 `SL-001` |

#### 成功响应

HTTP 200，返回最新一条 `telemetry` 记录。

### 3.4 POST `/api/telemetry/history`

用途：按设备和时间范围查询历史遥测数据，用于 ECharts 折线图、趋势图。返回结果按 `collectedAt` 升序排列。

#### 请求字段

| 字段 | 位置/类型 | 是否必填 | 说明 |
|---|---|---|---|
| `deviceId` | Body / String | 是 | 设备唯一编号，例如 `SL-001` |
| `startTime` | Body / DateTime | 是 | 查询开始时间，例如 `2026-07-02T00:00:00` |
| `endTime` | Body / DateTime | 是 | 查询结束时间，例如 `2026-07-02T23:59:59` |

#### 成功响应

HTTP 200，返回遥测数组。

如果时间范围内没有数据，返回空数组：

```json
[]
```

如果 `startTime` 晚于 `endTime`，返回 HTTP 400。

#### 请求示例

```http
POST /api/telemetry/history
Content-Type: application/json
```

```json
{
  "deviceId": "SL-001",
  "startTime": "2026-07-02T00:00:00",
  "endTime": "2026-07-02T23:59:59"
}
```

#### 成功响应示例

```json
[
  {
    "deviceId": "SL-001",
    "illuminance": 590,
    "temperature": 36.50,
    "humidity": 48,
    "pm25": 69,
    "aqi": 21,
    "pir": 1,
    "trafficFlow": 16,
    "collectedAt": "2026-07-02T11:56:29.876"
  }
]
```

## 5. 查询 SQL 与索引利用

### 5.1 设备列表与详情

设备查询统一过滤：

```sql
deleted = 0
```

避免返回逻辑删除数据。列表接口支持 `area` 和 `status` 两个可选条件，按 `area`、`device_id` 排序，便于前端稳定展示。

```sql
SELECT ...
FROM device
WHERE deleted = 0
  [AND area = #{area}]
  [AND status = #{status}]
ORDER BY area ASC, device_id ASC
```

### 5.2 最新遥测

最新遥测接口按 `device_id` 过滤，并按 `collected_at` 倒序取一条，满足实时卡片展示需求。

```sql
SELECT ...
FROM telemetry
WHERE device_id = #{deviceId}
ORDER BY collected_at DESC
LIMIT 1
```

### 5.3 历史趋势

历史趋势接口按 `device_id` 等值过滤，并对 `collected_at` 做时间范围查询，最后按 `collected_at` 升序返回。

```sql
SELECT ...
FROM telemetry
WHERE device_id = #{deviceId}
  AND collected_at >= #{startTime}
  AND collected_at <= #{endTime}
ORDER BY collected_at ASC
```

这条查询能利用数据库联合索引：

```text
idx_device_collected(device_id, collected_at)
```

原因是 SQL 先使用 `device_id` 等值条件，再使用 `collected_at` 范围条件，符合联合索引最左前缀使用方式。

## 6. 运行问题与修复记录

| 问题 | 原因 | 处理方式 |
|---|---|---|
| `JWT_SECRET` 解析失败 | 原逻辑只按标准 Base64 解码，无法兼容 Base64URL 字符 | `JwtUtil` 增加标准 Base64 与 Base64URL 兼容解码 |
| JWT 密钥过短 | JJWT 要求 HMAC 密钥至少 256 bit，即解码后不少于 32 字节 | `JwtUtil` 增加明确错误提示，指导生成合格密钥 |
| MQTT 断开后仍显示 published | `MqttPublisher` 捕获异常后不返回失败状态，`MockDataGenerator` 总是 `successCount++` | `MqttPublisher.publish` 改为 `boolean`，`MockDataGenerator` 仅在返回 `true` 时计数 |
| SQL 日志过多 | MyBatis-Plus 配置 `StdOutImpl` 后会打印每条 SQL | 确认为开发期正常日志，必要时可关闭 `log-impl` |
